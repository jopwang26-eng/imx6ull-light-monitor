# AP3216C 光照原始值首版

本驱动面向项目现有 Linux 4.1 BSP，通过已存在的 I²C 设备 `0-001e` 接管 AP3216C，不修改设备树。它只启用 ALS，提供 `/dev/lightap3216c`，不换算 lux。I²C1 还连接其他器件，不要禁用整个总线。首版不使用中断，也不开发 TCP。

每次 `read` 成功返回两个字节，低字节在前；非零且小于 2 的缓冲区返回 `EINVAL`，长度为 0 返回 0。I²C 错误向上传递，短传输返回 `EIO`，不会将旧值作为新值返回。读取的是当前寄存器值，不保证每次都是新一次转换。手动解绑后，旧文件描述符读取返回 `ENODEV`，关闭所有旧文件后才能重新绑定。

初始化复位后等待 50 ms，配置默认 ALS 量程，启用连续转换并等待 150 ms；先读取低字节以锁存高字节。依据 [AP3216C 数据手册 Rev. 0.86](https://device.report/m/5d492369365e9a621a41055004c360e24a3001a5571a1fa9be7908b76c0d3b2c) 第 13–18 页。

## 板端验证

先关闭所有使用 `/dev/ap3216c` 和 `/dev/lightap3216c` 的程序，在已启动现有测试 DTB 和 NFS 根文件系统的板端以 root 执行：

```sh
cd /opt/light_monitor
sh ./load_lightap.sh
./lightap_test -n 10 -i 1000
```

观察正常光照和遮挡时 `ALS_RAW` 是否变化。脚本检查绑定和节点，但不能替代实际读取；若失败，请保留完整输出以及 `dmesg | tail -n 40`。重新运行加载脚本可检查卸载重载后读取。完成后可恢复 BSP 原驱动：

```sh
sh ./restore_ap3216c.sh
```

工具支持 `-d DEVICE`、`-n COUNT`、`-i MS`；`-n 0` 持续采样至 Ctrl+C，间隔范围 100–60000 ms。读取失败或短帧时退出，不输出伪造样本。

## 构建与验证边界

在 Ubuntu 的实际工程目录，以目标内核构建外部模块；ARM 工具以 `-static` 构建。`tests/test_cli.py` 使用普通文件验证用户程序的两字节协议和失败行为，不模拟 I²C 或硬件。实际构建证据见 [验证记录](../../docs/validation/2026-11-04-ap3216c-als-build.md)；板端验收须另行记录实际输出。
