# 蜂鸣器 beep-v1.1 板端验收

2026-11-05，用户在独立蜂鸣器测试 DTB（启用 SION）启动后部署并测试正式清理版。日志确认 `beep-v1.1 ready: /dev/lightbeep default=off`，加载脚本回读 `GPIO_LOGICAL=0 (off)`。

`beep_api_test` 的独占打开 EBUSY、非法值与长度 EINVAL、无效读写指针 EFAULT、零长度读写、非法请求保持关闭、close 和 reopen 十项全部 PASS，`failures=0`。此前诊断版另有 `api_exit=0` 原始输出；本次正式版未单独打印退出码，不将该退出码移用于本次。

用户执行 on，工具输出 `GPIO_LOGICAL=1 (on)`；等待1秒后执行 rmmod，内核输出 `lightbeep remove, off_result=0`。再次加载成功并回读0，单独 status 也回读0。用户在此前要求确认卸载停止及重载无声的步骤后回复“均通过”，并补充上述正式版原始日志；实际发声另有“正常响了”的明确反馈。

正式版正常开关、默认关闭、接口边界、卸载关闭与重复加载已覆盖。控制失败返回依据源码审查：有返回值的方向输出调用传播错误，回读不符返回 EIO；早期初始化回读不符已实际触发EIO。尚未人为制造运行中关闭失败，不能据此宣称断线、负载损坏等故障已通过实测；该故障场景保留用于系统故障验证。

根因定位与 SION 对照见[诊断记录](2026-11-05-beep-probe-failure.md)。当前板上模块已重新加载、逻辑关闭。
