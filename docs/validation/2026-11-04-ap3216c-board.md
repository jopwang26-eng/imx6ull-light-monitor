# AP3216C ALS 板端初测

2026-11-04 用户提供串口输出：`load_lightap.sh` 显示 `lightap3216c 0-001e: als-v1 ready: bus=0 addr=0x1e node=/dev/lightap3216c` 和 `READY`。随后三次执行 `./lightap_test -n 20 -i 1000`，各输出 20 个样本；第一组主要为 62–64，第二组主要为 64–68，第三组先为 0、随后约 75–81、末尾又为 0。日志本身未标注遮挡时段，尚不能据此将变化确定归因于遮挡。期间出现一次独立的 `lightkey: debounced press` 日志。

再次运行加载脚本，日志先出现 `lightap3216c remove`，再出现 `als-v1 ready` 和 `READY`，证明重新加载及初始化成功。按正常光照、遮挡、移开的顺序采样：第 1–5 个为 83–87，第 6–10 个均为 0，第 11–15 个为 84–88；重载后读取成功且读数随光照变化。

用户执行 `sh ./restore_ap3216c.sh`，日志显示新驱动 remove 及 `RESTORED: /dev/ap3216c`；`readlink /sys/bus/i2c/devices/0-001e/driver` 指向 `bus/i2c/drivers/ap3216c`，`ls -l` 显示原字符节点主次设备号 10:62。原驱动绑定及节点恢复已验证，未再次测试其读取功能。

恢复原驱动后再次运行加载脚本，新驱动再次输出 `als-v1 ready`。板端 `dd if=/dev/lightap3216c of=/dev/null bs=1 count=1` 报告 `Invalid argument`、退出码 1，符合小于两字节缓冲区的 `EINVAL` 约定；随后 `lightap_test -n 3 -i 1000` 正常输出三个样本，值均为 0，当时光照状态未说明。

真实 I²C 故障返回尚未通过故障注入验证。样本为原始值，不是校准 lux。

随后正常光照下运行 `./lightap_test -n 5 -i 1000`，五个样本分别为 86、86、84、84、87；读数恢复到此前正常光照范围。
