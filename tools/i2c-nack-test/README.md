# 独立 I²C NACK 板测

前提：用户已确认没有额外I²C模块；当前总线0注册设备为0x0e、0x1e，测试地址0x1f未注册。注册列表不等同于总线扫描，故脚本仍要求明确的无额外设备参数。本工具不扫描总线。

build_ubuntu.sh将正式lightap3216c.c复制为base.c，通过包装模块只替换ALS读取处的事务入口。测试打开后对0x1f发一次单字节只读事务；负硬件返回原样进入正式驱动read，意外ACK则报EPROTO并判失败。初始化、正常读取、恢复均访问实际0x1e。BSP的i2c_imx_acked在无ACK时返回-EIO，本测试据此期待用户态errno=5。

run_board.sh临时卸载正式模块，加载独立模块，保持同一个fd验证正常、失败且缓冲区不被覆盖、恢复；再运行正式应用验证故障NA/报警关闭和恢复。退出trap恢复正式模块并重读。脚本不强制卸载，不改DTB/控制器/引脚，不写0x1f寄存器。正式源码和正式模块不覆盖。若恢复失败，应依据报告处理，不能宣称已经恢复。

此测试证明真实I²C适配器传输错误经驱动传播及应用处理，不能称为AP3216C实物断线、掉电或共享总线被拉死测试。构建成功仅表示工具准备，实际结论以板端报告为准。
